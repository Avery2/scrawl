# Scrawl — Agent Instructions

Scrawl is a macOS shortcut-triggered (`⌥⇧S`) screen, voice, cursor, and freehand drawing capture tool built in Rust + GPUI that compiles recordings into compact `.scrawl` bundles (`contact-sheet.png`, `frames/frame-XX.png`, `summary.md`, `scrawl.json`, `recording.mp4` or `recording.mov`, and `audio.wav`) in `~/Library/Application Support/scrawl/captures/`. It also captures a cabled iPhone (mirror + native video) and imports ScrawlKit in-app recordings (`scrawl import`, `Sources/ScrawlKit`); see README for both and for testing.

## Continuous Output Review & Proactive Recommendations

- **Always inspect real capture artifacts**: Whenever working on Scrawl or after Kit tests a capture, inspect the latest bundles in `~/Library/Application Support/scrawl/captures/` (both `summary.md` / `scrawl.json` and visual `contact-sheet.png` / `frames/*.png` via `read`).
- **Proactively recommend improvements**: Continuously look for and surface concrete improvements whenever you spot issues in the output or UX—such as redundant or noisy text in `summary.md`, cluttered or low-density `contact-sheet.png` layouts, unnecessary keyframes (e.g. static frames cut on speech pauses), ghost strokes or misaligned annotations, slow startup or post-processing latency, or clipboard/paste friction.

## Design & Architecture Principles

- **Division of labor between Images and Text**:
  - **Images (`frames/*.png` and `contact-sheet.png`)**: Keep images purely visual. Each keyframe shows the screenshot, active red tldraw stroke(s) for that moment, click ripple/cursor, and a compact `#N · M:SS` corner badge. `contact-sheet.png` is a tight grid of those labeled frames with no rasterized transcript headers or caption boxes.
  - **Text (`summary.md` & Clipboard)**: Put the transcript, `[#N · M:SS]` keyframe index, and absolute file paths (`Contact sheet:`, `frames/frame-XX.png`, `Video:`, `Bundle:`) in plain text (`NSPasteboardTypeString`) without repeating the transcript multiple times, so `⌘V` pastes cleanly into any terminal (Ghostty / OpenCode TUI) or GUI composer (OpenCode Desktop).
- **Shortcuts (`src/hold.rs`, `is_capture_shortcut` in `src/capture.rs`)**: `⌥⇧S` (or the configured shortcut) works like `⌘Tab`. A tap (modifiers up within 250 ms) records the display under the pointer at once, auto-cropped, with a brief red edge glow from the overlay as the start cue. Held, the switcher opens on Screen; each further S steps Screen → Window → iPhone, a mouse drag selects an area, Esc cancels, and releasing the modifiers records the selection. While recording, a tap finishes, ignoring one within 400 ms of the start. The menu's **Choose What to Record…** opens the full picker. Carbon hotkeys, the event tap and the HID poller report presses through `emit_capture_shortcut` (deduplicated within 90 ms); the UI loop polls the modifiers and Esc (`tick_switcher`), so the release is seen whichever window has focus.
- **Keyframe selection (`src/keyframes.rs`)**:
  - Only cut keyframes on real visual or input events (`Mark` strokes drawn while holding `⇧`, flags, `Click`/`Drag` inside the capture target or phone taps/swipes, `Laser` points, or settled `SceneChange` transitions)—never cut extra keyframes on speech pauses alone over a static screen.
  - The one speech exception is a spoken cue with measured word timings (SpeechAnalyzer, or Hex words it returned itself, never times spread over speech islands): "now", "here", "look", "watch" snap to a transition that starts within −0.3 s…+1.2 s of the word, else take the frame 150 ms after it. A cue keyframe is dropped unless its image differs (scene diff ≥ 0.03) from every keyframe already chosen, so speech over an unchanged screen still yields one frame. Demonstratives and "see"/"there" are weak (they rank with ordinary scene changes) because they are usually filler.
  - Text per keyframe: each keyframe owns the words from the start of the clause in progress at its anchor (action start, transition start, or cue word) until the next keyframe's start. Clauses break at clause punctuation, recognizer segment starts, or a ≥1.5 s pause. Words before the first keyframe belong to it.
- **Mac captures (`src/capture.rs`)**: the sampler keeps only small candidates (480 px long edge, in a `CandidateBuffer` capped at 384 MB that thins evenly and halves its sampling rate when full, never dropping the start or click/stroke frames). At finish the chosen keyframes are decoded from `recording.mp4` at native size (2560 px Screen, 1280 px Window/Region), shifted by `videoOffsetMs` (when the movie started on the capture clock); if decoding fails the candidates are used. `scrawl capture-sim` drives this headless for memory and timing checks.
- **iPhone sources (`src/phone.rs`, `helper/`)**:
  - `scrawl-helper` (Swift, built by `build.rs` into `target/<profile>/`, copied and signed into `Scrawl.app/Contents/MacOS` by `install-app.sh`) does SpeechAnalyzer, CoreMediaIO/AVFoundation phone capture with the mirror window, and movie decoding. Swift was chosen over objc2 bindings because SpeechAnalyzer has no Objective-C surface and `objc2-av-foundation` is not in the lockfile.
  - Picker discovery (`scrawl-helper devices`) reads the USB registry only: it is instant and never touches AVFoundation, so opening the picker can't raise a camera prompt or hang. Only the mirror, started when iPhone is chosen, asks for camera access.
  - Live capture: the mirror window's rect (global top-left points, streamed by the helper) is the telemetry target, so ink/laser/clicks normalize into phone coordinates; inputs are re-based onto the movie's clock (`recording.startedAt`) at finish. Keyframes are selected on 320 px candidates and re-decoded from the native video at a 1600 px long edge.
  - Audio for transcription is always the movie's audio exported on the asset timeline (`scrawl-helper audio`). Do not feed a `.mov` straight to SpeechAnalyzer: `AVAudioFile` ignores the movie timeline and its word times drift (≈1.5 s late at 41 s on a phone recording).
- **Fast builds & local workflow**:
  - Keep `Cargo.toml` and `Cargo.lock` stable and build/test with `taskpolicy -c utility cargo build -j 3 --offline` and `taskpolicy -c utility cargo test -j 3 --offline -- --test-threads=2`.
  - Keep everything local on `main` unless asked otherwise.
  - Agents: `install-app.sh` starts the app with `nohup` from your shell, and the agent's shell tool can kill it when the command returns. If `pgrep -fl Scrawl.app` shows nothing afterwards, relaunch with `open -a ~/Applications/Scrawl.app`.
  - **Installing on another Mac (e.g. from the Studio onto the MacBook Pro):** run `./scripts/install-app-remote.sh pro`. Running `install-app.sh` over SSH can't sign (no keychain), and running it as a launchd job can't write into the installed app (App Management), so the remote script signs a staging copy in a launchd job and copies it into place over SSH.
  - **Always install and launch via `./scripts/install-app.sh` (`~/Applications/Scrawl.app`)**: Never run `target/debug/scrawl` directly as the background daemon because `hivemind clean` purges `target/` directories, which unlinks the binary on disk and causes macOS `tccd` to revoke Screen Recording and Microphone access. `./scripts/install-app.sh` copies the binary into `~/Applications/Scrawl.app`, signs it with Kit's Developer ID (`dev.kitlangton.scrawl`) so TCC permissions persist across rebuilds, and restarts the app.
