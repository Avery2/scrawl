# Scrawl — Agent Instructions

Scrawl is a macOS shortcut-triggered (`⌥⇧S`) screen, voice, cursor, and freehand drawing capture tool built in Rust + GPUI that compiles recordings into compact `.scrawl` bundles (`contact-sheet.png`, `frames/frame-XX.png`, `summary.md`, `scrawl.json`, `recording.mp4` or `recording.mov`, and `audio.wav`) in `~/Library/Application Support/scrawl/captures/`. It also captures a cabled iPhone (mirror + native video) and imports ScrawlKit in-app recordings (`scrawl import`, `Sources/ScrawlKit`); see README for both and for testing.

## Continuous Output Review & Proactive Recommendations

- **Always inspect real capture artifacts**: Whenever working on Scrawl or after Kit tests a capture, inspect the latest bundles in `~/Library/Application Support/scrawl/captures/` (both `summary.md` / `scrawl.json` and visual `contact-sheet.png` / `frames/*.png` via `read`).
- **Proactively recommend improvements**: Continuously look for and surface concrete improvements whenever you spot issues in the output or UX—such as redundant or noisy text in `summary.md`, cluttered or low-density `contact-sheet.png` layouts, unnecessary keyframes (e.g. static frames cut on speech pauses), ghost strokes or misaligned annotations, slow startup or post-processing latency, or clipboard/paste friction.

## Design & Architecture Principles

- **Division of labor between Images and Text**:
  - **Images (`frames/*.png` and `contact-sheet.png`)**: Keep images purely visual. Each keyframe shows the screenshot, active red tldraw stroke(s) for that moment, click ripple/cursor, and a prominent high-contrast `#N M:SS` corner badge (white `#N` keycap + dark `M:SS` pill, top-left by default and dodging to top-right when top-left has ink/clicks). `contact-sheet.png` packs frames in time order (left→right, top→bottom) into aspect-ratio-justified rows separated by tight 6 px gutters on a dark canvas (no card borders or rounded frame masks, capped at 1600 px long edge / ~1.56 MP) with no rasterized transcript headers or caption boxes.
  - **Text (`summary.md` & Clipboard)**: Put the transcript, `[#N · M:SS]` keyframe index, and absolute file paths (`Contact sheet:`, `frames/frame-XX.png`, `Video:`, `Bundle:`) in plain text (`NSPasteboardTypeString`) without repeating the transcript multiple times, so `⌘V` pastes cleanly into any terminal (Ghostty / OpenCode TUI) or GUI composer (OpenCode Desktop).
- **Shortcuts (`src/hold.rs`, `is_capture_shortcut` in `src/capture.rs`)**: `⌥⇧S` (or the configured shortcut) works like `⌘Tab`. A tap (modifiers up within 250 ms) records the display under the pointer at once, auto-cropped, with a brief red edge glow from the overlay as the start cue, and the capsule springs open onto switch chips (Area · Window · Screen · iPhone if cabled; `hold::Reveal`, `REVEAL_*` constants at the top of `src/ui.rs`) until 3.5 s pass or the user clicks, scrolls or draws (never while hovered). A chip (`switch_recording`) restarts rather than retargets: Window/Area discard the few seconds and morph the capsule into the non-held picker, iPhone discards and starts the phone. Held, the switcher opens on Screen; each further S steps Screen → Window → iPhone, a mouse drag selects an area, Esc cancels, and releasing the modifiers records the selection. While recording, a tap finishes, ignoring one within 400 ms of the start. The menu's **Choose What to Record…** opens the full picker. Carbon hotkeys, the event tap and the HID poller report presses through `emit_capture_shortcut` (deduplicated within 90 ms); the UI loop polls the modifiers and Esc (`tick_switcher`), so the release is seen whichever window has focus.
- **Video export (`src/export/`, `helper/Export.swift`)**: `scrawl export <bundle>` writes one H.264/HEVC + AAC `.mp4`; the `videoExport` flag (default off) only gates the menu's **Export Last Capture as Video…** (→ `~/Movies/Scrawl`, progress beside the menu bar icon). Rust decides everything and the helper renders it from a JSON plan (AVAssetReader → Core Image crop/camera → Core Graphics ink → AVAssetWriter): `crop.rs` (`--crop auto|full|x,y,w,h` — auto is `autocrop` `Scope::Whole` — even-sided output size, audio window), `ink.rs` (strokes via `sketch::freehand_outline`, laser, pins, ripples; sizes mirror `render::annotate_keyframe_in_place`), `camera.rs` (`--zoom`: pure events → camera rects, critically damped springs, never zooms during fast cursor travel; derived from ScreenDemon's click zoom). Everything in the plan is on the video's clock (bundle time − `videoOffsetMs`); Mac `audio.wav` starts `videoOffsetMs` in, an iPhone movie uses its own audio. Output is constant frame rate (screen movies only have frames on change). Test with `cargo test export::`.
- **Onboarding (`src/onboarding.rs`, `helper/Onboarding.swift`)**: Rust decides what shows (`Flow`, `launch_plan`, `Gate`, tested) and stores progress under `"onboarding"` in `~/.config/scrawl/config.json`, including the tour's current step (`resume`), so any quit (macOS's "Quit & Reopen" too) picks up there; the SwiftUI window in `scrawl-helper onboarding` only renders the state it's sent and reports buttons (`grant:<permission>` for a row). Tour: Welcome → HowItWorks → Permissions (one checklist: Screen Recording, Microphone, Input Monitoring, all required, granted in any order) → TryIt → Done. Accessibility (⌥⇧V, the Paste chip) and Camera (iPhone) are never in the tour: their first use opens `Flow::fix(vec![p])`, the same screen with one row. Grants are re-read every 0.5 s from a fresh `scrawl-helper permissions`; the coordinator caches them (`ScrawlCoordinator::grants`). A Screen Recording grant only reaches this process after a relaunch (Apple's ScreenCaptureKit sample and DTS say so; `CGPreflightScreenCaptureAccess` caches), so the Permissions screen relaunches at most once, after every required row is granted, and the tour resumes at TryIt. Input Monitoring needs no relaunch: `note_grants` calls `capture::restart_input_tap` when it turns on. Until the required ones are on, ⌥⇧S and the menu's record items start nothing (no switcher, picker or overlay; the picker sits at `NSStatusWindowLevel + 1` and takes clicks, which trapped macOS prompts under it): `Gate` holds the request and `tick_gate` opens or raises the window once the modifiers are up. Capture code must not call `CGRequestScreenCaptureAccess` or start the iPhone mirror without Camera: go through `ready_to_record` / `ready_for`. Render every screen and permission state with `scrawl-helper onboarding --render DIR`. Rows for draggable lists (`Permission::draggable`: Screen Recording, Input Monitoring, Accessibility) go straight to `OpenSettings`, which launches `scrawl-helper permission-panel` (`helper/PermissionPanel.swift`) from the row's button: the card flies to just below System Settings, drags the `Scrawl.app` that contains the helper, reads grants from a fresh `--check` process (never trusts the drop), and is told `granted` when the row turns on. Preview it with `permission-panel --permission screen-recording --preview`; never `tccutil reset` Kit's real grants to test it.
- **Transcription (`src/transcribe.rs`, `src/hex.rs`)**: Apple SpeechAnalyzer by default (measured word times). `"transcriber": "hex"` + `"hexModel"` in `~/.config/scrawl/config.json` (menu **Transcription**, `scrawl hex status`, `--transcriber` on `reprocess`/`import`) uses Hex's local API v2 (discovery file `local-api.json`, bearer token, never logged) only when Hex answers `/health` and has a ready model (`installed && verified`; Scrawl never downloads). Hex gives text only, so each speech island (`audio::speech_islands`, clips merged to ≤ 24) is transcribed on its own and its words are spread over it by length: `source: "hex:<model>"`, `estimated: true`, which `keyframes.rs` reads to skip spoken cues. Any Hex failure falls back to Apple for that recording; Hex absent falls back silently (logged once). The menu reads `hex::cached_status` (a background poller), never the network.
- **Keyframe selection (`src/keyframes.rs`)**:
  - Only cut keyframes on real visual or input events (`Mark` strokes drawn while holding `⇧`, flags, `Click`/`Drag` inside the capture target or phone taps/swipes, `Laser` points, or settled `SceneChange` transitions)—never cut extra keyframes on speech pauses alone over a static screen.
  - The one speech exception is a spoken cue with measured word timings (SpeechAnalyzer; never a Hex transcript, whose times are `estimated`): "now", "here", "look", "watch" snap to a transition that starts within −0.3 s…+1.2 s of the word, else take the frame 150 ms after it. A cue keyframe is dropped unless its image differs (scene diff ≥ 0.03) from every keyframe already chosen, so speech over an unchanged screen still yields one frame. Demonstratives and "see"/"there" are weak (they rank with ordinary scene changes) because they are usually filler.
  - Budget (`keyframe_budget`): 6 up to 40 s, then one more per 20 s, at most 12 (each image costs a reading model ~1–1.5k tokens). Ordinary events fill only the first 6; the rest are for marks and coverage.
  - Marks are never dropped. Marks drawn on the same screen share one keyframe at the last of them, which draws all their ink (`mark.frame` names it; `markId` is the first): the screen counts as the same while the luma grid around their ink, padded by 8%, changed in under 5% of its cells. A group closes at a click or drag, past 20 s, or past 12 strokes. Groups beyond the budget merge with a neighbour: same-screen pairs with the least ink first, else the most alike screens. Flags stay on their own. No other keyframe cuts into a multi-mark group's span. Auto-crop gives a group's ink to its keyframe's crop alone (`Input::pin_ink`).
  - Coverage: after marks, a stretch longer than 100 words or 35 s gets a frame from inside it when one qualifies (a click, laser, settled scene change or novel cue); the lead-in before the first keyframe is its own stretch. Speech over an unchanged screen still yields one frame.
  - Text per keyframe: each keyframe owns the words from the start of the clause in progress at its anchor (action start, transition start, or cue word) until the next keyframe's start. Clauses break at clause punctuation, recognizer segment starts, or a ≥1.5 s pause. Words before the first keyframe belong to it.
- **Mac captures (`src/capture.rs`)**: the sampler keeps only small candidates (480 px long edge, in a `CandidateBuffer` capped at 384 MB that thins evenly and halves its sampling rate when full, never dropping the start or click/stroke frames). At finish the chosen keyframes are decoded from `recording.mp4` at native size (2560 px Screen, 1280 px Window/Region), shifted by `videoOffsetMs` (when the movie started on the capture clock); if decoding fails the candidates are used. `scrawl capture-sim` drives this headless for memory and timing checks.
- **iPhone sources (`src/phone.rs`, `helper/`)**:
  - **Delivery recovery:** Read the original `timeline.json` before re-sending an imported capture. Its top-level `session` is the configured destination; `context.session` only names the session visible in the recorded app. Never use the latter to choose `scrawl send --session`. `scrawl send` without `--session` uses the top-level destination and refuses a different `--session` unless `--reroute` is passed (`handoff::recorded_destination`). After changing Rust code, rebuild with `cargo build` before running `target/debug/scrawl`: `cargo test` does not rebuild the binary. Preserve an explicit destination during recovery, check whether it already received the capture, and ask before overriding it. If no destination is recorded and app ownership is ambiguous, ask rather than guessing from the viewed session or recent activity. Do not change a private project's endpoint or recipient as a recovery shortcut.
  - `scrawl-helper` (Swift, built by `build.rs` into `target/<profile>/`, copied and signed into `Scrawl.app/Contents/MacOS` by `install-app.sh`) does SpeechAnalyzer, CoreMediaIO/AVFoundation phone capture with the mirror window, and movie decoding. Swift was chosen over objc2 bindings because SpeechAnalyzer has no Objective-C surface and `objc2-av-foundation` is not in the lockfile.
  - Picker discovery (`scrawl-helper devices`) reads the USB registry only: it is instant and never touches AVFoundation, so opening the picker can't raise a camera prompt or hang. The first time iPhone is chosen without Camera, Scrawl closes the picker and opens the onboarding window's Camera row instead of starting the mirror (whose prompt would land under the picker).
  - Live capture: the mirror window's rect (global top-left points, streamed by the helper) is the telemetry target, so ink/laser/clicks normalize into phone coordinates; inputs are re-based onto the movie's clock (`recording.startedAt`) at finish. Keyframes are selected on 320 px candidates and re-decoded from the native video at a 1600 px long edge.
  - ScrawlKit ingest (`ingest_recording`, `src/delivery.rs`): the Mac answers an upload only after the bundle is built and queued into OpenCode, or after the phone's `X-Scrawl-Wait` (default 25 s, max 45 s): `200 {"ok","delivered","state":"sent"|"queued"|"saved"|"processing","sessionTitle","error"?}`; a failed build answers 500 and forgets the recording so it can be sent again. Copies of one recording (LAN + Tailscale, HTTP + USB, keyed by `recordedAt`) wait for the first and get its outcome. A failed forward is `queued`: the bundle gets `.deliver.json` and the port owner retries it (15 s doubling to 30 min, for a day, then `.deliver-failed.json`); the phone never re-uploads for it, and retention skips the bundle. Over USB the Mac writes `<stamp>.delivery` (the same JSON) before `<stamp>.sent` (the session name, all older ScrawlKit reads). ScrawlKit's `IngestReply` treats a reply without `delivered` as sent. Tests swap the outside steps through `IngestHooks`; never post to a real session.
  - Audio for transcription is always the movie's audio exported on the asset timeline (`scrawl-helper audio`). Do not feed a `.mov` straight to SpeechAnalyzer: `AVAudioFile` ignores the movie timeline and its word times drift (≈1.5 s late at 41 s on a phone recording).
- **Dev-site routing (`src/routing.rs`, `src/web.rs`, `src/sdk.js`)**: a Screen capture that ends with a browser in front (Window mode: the captured app) reads the tab URL with `osascript` (6 s cap, for the one-time Automation prompt) while the bundle is built, then picks a session: a live `/sdk.js` registration for the tab's origin (`data-session`, or `data-directory` → newest open root session there), else for a loopback URL the port's listener (`lsof`) → cwd → git root → newest open root session inside it (`list_root_sessions`, V2 `location.directory`). The choice is written to `scrawl.json` `destination` and the summary's second line, then sent through `delivery::deliver` (same `.deliver.json` retries as iPhone). `recorded_destination` prefers a timeline's `session`, then `destination.session`. `/sdk.js` and `/web/*` on the ingest port skip the bearer check only for a loopback `Origin` from a loopback peer (`web::may_register`); `/web/registrations` needs the token. `scrawl route --url` prints the decision without sending; tests swap the outside steps through `routing::Hooks`. Off with `"autoSend": false`.
- **Retention and shrinking (`src/retention.rs`, `Media.shrink` in `helper/Media.swift`)**: the app's `retention` worker (utility QoS) runs a pass 90 s after launch and daily: heavy media (`handoff::HEAVY_MEDIA`) to the Trash after `mediaDays` (default 7, writes `.media-cleaned`), whole bundles after `bundleDays` (30); `"retention"` in `~/.config/scrawl/config.json`, menu **Keep Recordings**. It skips bundles under a day old or whose folder changed (ctime) in the last day, live `.media-pending`/`.media-sending` markers, `.pinned`, `.deliver.json`, and bundles `retention::claim`ed. Cabled-iPhone `recording.mov` (> 6 Mbps) is re-encoded to HEVC at 1600 px a minute after `finalize_live_capture`, written beside the bundle and renamed over the original; sample times are kept, so `scrawl.json` is unchanged. Anything reading `video` must handle it missing (`retention::missing_media_reason`). Try passes on a temp folder with `scrawl clean --captures DIR --days-ahead N [--dry-run]`.
- **Fast builds & local workflow**:
  - Keep `Cargo.toml` and `Cargo.lock` stable and build/test with `taskpolicy -c utility cargo build -j 3 --offline` and `taskpolicy -c utility cargo test -j 3 --offline -- --test-threads=2`.
  - Keep everything local on `main` unless asked otherwise.
  - Agents: `install-app.sh` starts the app with `nohup` from your shell, and the agent's shell tool can kill it when the command returns. If `pgrep -fl Scrawl.app` shows nothing afterwards, relaunch with `open -a ~/Applications/Scrawl.app`.
  - **Installing on another Mac (e.g. from the Studio onto the MacBook Pro):** run `./scripts/install-app-remote.sh pro`. Running `install-app.sh` over SSH can't sign (no keychain), and running it as a launchd job can't write into the installed app (App Management), so the remote script signs a staging copy in a launchd job and copies it into place over SSH.
  - **Always install and launch via `./scripts/install-app.sh` (`~/Applications/Scrawl.app`)**: Never run `target/debug/scrawl` directly as the background daemon because `hivemind clean` purges `target/` directories, which unlinks the binary on disk and causes macOS `tccd` to revoke Screen Recording and Microphone access. `./scripts/install-app.sh` copies the binary into `~/Applications/Scrawl.app`, signs it with Kit's Developer ID (`dev.kitlangton.scrawl`) so TCC permissions persist across rebuilds, and restarts the app.
